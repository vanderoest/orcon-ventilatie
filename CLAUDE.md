# Token efficiency

Be extremely conservative with token usage.

The feature has already been designed.

Treat every design decision in this prompt as authoritative.

Do not redesign, reconsider or debate the requested behaviour.

Your task is to produce an implementation plan, not a design study.

Read only the repository files required to understand the existing implementation.

Avoid rereading files.

Reuse previous findings instead of rediscovering them.

Avoid duplicate analysis.

Do not perform work that has explicitly been ruled out in this prompt.

When using sub-agents:

- Spawn sub-agents only when they reduce total token usage.
- Give each sub-agent only the minimum context required for its task.
- Never provide the full repository context unless absolutely necessary.
- Merge their results instead of asking multiple agents to analyse the same problem.

Prefer targeted modifications over large rewrites.

Avoid speculative architecture discussions.

Avoid unnecessary explanations.

Produce concise implementation plans.

Minimize total token consumption while maintaining implementation quality.
